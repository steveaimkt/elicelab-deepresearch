# 4교시 딥리서치 에이전트 구축 (게이트형·독립)

> 이 스킬은 게이트형이다. 한 번에 다 실행하지 말 것.
> 게이트 하나 = 응답 하나 + 질문 하나. 수강생 답을 받고 다음 게이트로 넘어간다.
> 목표: 질문 → 스킬 → MCP → 결과물(pptx) → 발송까지 **한 번에 완성**해서 결과물을 손에 쥔다.
> 나가는 건 반드시 묻는다(승인 게이트).

## 진행 원칙 (Claude가 지킬 것)

1. 한 게이트씩: 현재 게이트만 안내하고 수강생의 완료 응답을 기다린다
2. 복붙 우선: 수강생이 입력할 프롬프트는 코드 블록으로
3. 진행 현황 표시: 매 게이트 시작 시 `[G번호 · 제목]`
4. **주제는 직무에 맞게**: G1에서 직무 팔레트로 각자 자기 주제를 고르게 한다
5. **파일이 눈에 보이게**: SKILL.md가 왼쪽 탐색기에 뜨는 걸 확인시킨다
6. **결과물 pptx는 2방식 택1**: python 템플릿 / pptx 프롬프트. 둘 다 하지 않는다
7. **외부 전송은 승인 게이트**: Gmail로 보내기 전에 반드시 묻는다
8. 시간이 부족하면: Gmail 발송을 생략한다. **에이전트 파일과 결과물은 반드시 남긴다**

## 시작 멘트

```
4교시를 시작합니다. 오늘의 종착점입니다.

지금까지는 매번 손으로 시켰습니다. "넓게 찾아줘, 출처 없으면 버려줘, 수요도 봐줘…"
오늘은 그 규칙을 파일 한 장에 박고, 실행해서 결과물(보고서)까지 뽑고, 메일로 보냅니다.
질문 하나에서 시작해 발송까지, 한 번에 완성합니다.

만들 것: 딥리서치 에이전트 (SKILL.md) + 보고서(pptx) + 발송

5단계로 갑니다 (약 55분):

  G1  리서치 질문 (직무별)     (8분)
  G2  스킬 구축 ★             (17분)
  G3  MCP 연결                (5분)
  G4  결과물 pptx ★           (15분)  ← python 템플릿 / pptx 프롬프트 중 택1
  G5  메일 발송 ★             (10분)  ← 나가는 건 반드시 묻는다

준비되셨으면 "시작"이라고 입력해 주세요.
```

# G2. 스킬 구축 ★ (17분)

목표: 수집·검증 규칙을 파일로 굳힌다. **이 파일이 여러분의 에이전트다.**

Claude가 먼저 출력한다 (에이전트 3요소):

```
에이전트는 딱 3가지로 이루어집니다.

  ① 입력  무엇을 받는가          → 조사 주제 한 줄
  ② 규칙  어떻게 일하는가         → 수집 방법 + 검증 규칙  ★ 여기가 핵심
  ③ 출력  무엇을 내놓는가         → 조사결과 + 보고서

  대부분은 ①과 ③만 생각합니다. 품질은 ②에서 갈립니다.
```

Claude 멘트 포인트: "지금 만드는 SKILL.md 한 장이 에이전트 본체입니다. 검증 규칙이 글로 담기는 걸 왼쪽 탐색기에서 눈으로 보세요."

따라하기:
```
딥리서치 에이전트를 만들어줘.
`4교시 실습 결과/딥리서치-에이전트/SKILL.md`로 저장해줘.

입력: 조사 주제 한 줄

수집 규칙 (두 도구를 순서대로):
  ① Firecrawl 검색   관련 기사·페이지를 넓게 찾는다 (10건 이상)
  ② Firecrawl 본문   중요한 자료는 원문 본문을 통째로 가져온다
  ③ 데이터랩        핵심 키워드의 검색 추이(수요)를 확인한다

교차 규칙:
  · 기사·원문은 "뜬다"는데 데이터랩 검색량이 안 늘면 그 주장을 보류한다
  · 원문(내용)과 수요(숫자)가 엇갈리는 지점을 반드시 기록한다. 그게 인사이트의 씨앗이다

검증 규칙 (3단, 반드시 이대로):
  ① 출처 추적  모든 문장에 출처 링크를 붙인다. 못 붙이면 그 문장은 버린다
  ② 교차 확인  같은 사실이 다른 출처에도 있는지 본다. 한 곳뿐이면 "미확인" 표시
  ③ 환각 점검  틀린 전제를 넣어도 맞장구치지 않는다. 근거 없으면 "모른다"고 답한다

출력: `4교시 실습 결과/조사결과.md` — 아래 구조로 저장한다 (pptx가 이 형식을 그대로 읽는다):
  # {제목}
  메타: {한 줄} / 질문: {질문} / 결론: {결론} / 결론보충: {한 줄}
  ## 인사이트   - [반전] {한 줄} :: {보충}   (비교·결정영향도 같은 형식)
  ## 반대 근거  반대핵심: {형광 강조어} / 반대문장: {이어지는 말} / 반대보충: {한 줄}
  ## 액션       - {액션 1~3}
  ## 출처       출처요약: {확인 n/미확인 n/버림 n} / - {출처들} / 버림: {버린 것}
```

Claude 실행 규칙:
- SKILL.md를 실제 파일로 만들고 **열어서 보여준다**
- frontmatter에 name, description, 트리거를 넣는다 (트리거는 수강생이 정한다)
- `조사결과.md`는 위 형식을 정확히 따르게 한다 (pptx 템플릿·프롬프트가 이 형식을 읽는다)

✅ 체크포인트: "왼쪽 탐색기에 SKILL.md가 보이나요? 검증 규칙 3줄을 확인하셨나요?"

```

### 방식 ① python 템플릿 실행
따라하기:
```

Claude 실행 규칙: `조사결과.md`가 템플릿 형식에 맞는지 확인 후 `python3 보고서_pptx_템플릿.py` 실행. 6장(표지·결론·인사이트·반대근거·액션·출처) WMBB deck 생성.

## 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| MCP 도구가 안 보임 | 실습 파일 키 미입력 / 재시작 안 함 | 조교가 `.mcp.json`에 키만 붙여준다. IDE 재시작 |
| 네이버 401 인증 실패 | ID/Secret 뒤바뀜 | **ID가 긴 값, Secret이 짧은 값** |
| 에이전트가 규칙을 무시한다 | SKILL.md가 안 읽힘 | "SKILL.md 읽고 그대로 해줘"로 명시 |
| python 템플릿이 안 돈다 | python-pptx 미설치 | 방식 ②(pptx 프롬프트)로 전환. 설치 불필요 |
| pptx 색이 다르다 (방식 ②) | 생성기가 자체 템플릿 적용 | 표지가 어두운 템플릿을 고른다. 구조·내용은 프롬프트가 고정 |
| Gmail 커넥터가 목록에 없음 | 환경 차이 | 없으면 결과물 파일만으로 완주 |
| Gmail 연결이 안 됨 | 회사 계정 보안 | 개인 Gmail로 연결 |
| 시간이 부족하다 | 진도 지연 | Gmail 생략. **에이전트 파일과 pptx는 반드시 남긴다** |
